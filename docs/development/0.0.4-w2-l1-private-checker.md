## Implementation and trust argument

The checker uses a fresh 0700 child beneath fixed `/run`, not ambient TMPDIR,
TEMP, TMP, cached tempfile state, a command-line override or the output parent.
The initial proposal described validated output-parent staging. Fixed `/run`
keeps checker executable ancestry independent of output/source fixture paths,
avoids broadening existing source-input ancestry rules, and adds no persistent
service or directory. `/run` must already exist as a real directory beneath
root-owned, non-group/world-writable, non-special-mode ancestors without
unreviewed xattrs/ACLs. Failure rejects the operation. This compatibility
requirement is deliberate and must be validated in the disposable test guest.

Every ancestor is opened without following links and its directory identity,
ownership/mode and mount ID retained. Mount transitions such as a private
`/run` tmpfs are allowed, but observed mount-identity changes are rejected.
Captured artifact/parser bytes are created exclusively through held directory
descriptors at 0400. Their full metadata, link count, xattrs, mount, pathname
identity and exact bytes are rechecked before and after the parser invocation.
The independent parser, reviewed hash argument, timeout and report checks stay
in `read_artifact`; the supplied ELF is never executed.

The security argument is absence of an untrusted writer's replacement ability
in every ancestor plus an inaccessible private child, not atomic pathname
rechecking. Trusted root/kernel/mount administrators can still race these
checks and are outside this boundary. Serial/private test contexts remain
necessary; this does not fix I1 output-publication races.

Cleanup unlinks only the two known names relative to the held child descriptor,
then removes the child relative to the held parent. It does not recurse through
a mutable pathname. Detected child replacement is preserved and rejected.
A trusted-root relocation can leave the original directory empty, but cleanup
removes the captured files from that held original directory; this is not a
claim to remove arbitrary aliases made by hostile root. Unexpected entries or
cleanup failure fail closed rather than authorize publication. Ordinary cleanup
errors and attacker-introduced unexpected entries/substitution are distinct:
the latter may deliberately preserve evidence. Zero survivors is not promised
for hostile-root modifications or an underlying filesystem cleanup failure.

## Concurrent test source: execution pending

`test_concurrent_unprivileged_attempts_during_parser_validation` now implements
the bounded concurrent test source; it has NOT RUN. Both private-ancestor 0700
and accessible-but-root-owned 0755 cases retain a 0700 staging child. The second
case requires successful unprivileged listing/traversal of the outer fixture
ancestors, so denials cannot be attributed only to their privacy.

A forked worker closes inherited staging/ancestor descriptors and verifies only
its reporting socket remains above stdio. It clears supplementary groups,
drops real/effective/saved gid and uid to mapped identity 1, and verifies those
identities plus zero effective, permitted and ambient capabilities. Setup
errors are failures, never attack detections. The parent releases the worker
through a socket barrier for 32 rounds per case. Each round attempts capture
read, checker write, private-child creation, child rename and parent symlink
creation while the parent validates; every eighth round also invokes the real
trusted Python parser over synthetic ELF bytes. Every operation must receive
EACCES/EPERM. Identity and errno observations are printed for retained logs.

Socket waits, parser calls and child exit have five-second bounds. On failure,
only the parent's unreaped worker is terminated/reaped. The parent checks
parser success and exact hashes, final unchanged captured bytes, child exit
and ordinary staging cleanup. Attempts and independent processes are real
when executed, but no exact syscall interleaving, exhaustive scheduling or
hostile-root resistance is claimed. No ELF is executed and no host account,
security setting, capability grant or filesystem permissions are changed.
All identity and fixture-permission changes belong only to the approved
disposable Linux namespace; do not run this test on the Mac or shared host.

Native race execution, recorded actual DAC refusals, all suite/mutation results
and the existing reviewed-F5 roundtrips remain mandatory pending gates.
