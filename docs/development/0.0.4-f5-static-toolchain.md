## Measured compilation and compatibility

`tools/build-static-fixture` prepares its separate, network-disabled rootless
builder using only the locked local RPMs. It accepts only the fixed reviewed
fixture source and flags. Two independent clean, read-only compilation
containers produced the same binary SHA-256:

`deeae34d74b6933d7b3ee88b7780a340a19267cc7eac0bee1320226adee93093`.

Builder config ID:
`sha256:b9ae6819081694488629707814df7415ade1f3d492e0e959ea0b72c7335dde80`.
Measured local builder manifest digest:
`sha256:ec5c37401f92604eb844e9628db51b84eb97f05429626e340b5a76a8de47bfc9`.
Both binaries are 15,725,600 bytes. The builder remains local and unpublished.

The separate ELF parser accepted both results: x86_64, valid executable entry,
no `PT_INTERP` or `DT_NEEDED`, no executable stack or writable/executable load
segment. Header, program, dynamic and unstripped symbol listings are retained.
The fixed binary ran successfully on the **original** pinned base as UID/GID
65532, with read-only root, network disabled and all capabilities dropped:
exit 0 and exactly `SignalLayer Candidate C fixture\n`.

This proves the fixed compilation and success path, not generic glibc
self-containedness. The binary contains loader-related symbols (`dlopen`,
`dlsym`) and source-unit symbols related to address/user lookup; `nm -u` also
reports `__tls_get_addr`. Symbol presence alone neither proves a call on this
path nor an external dependency. The base smoke includes existing libraries
and configuration; empty-root execution, generic NSS/dlopen/locale independence
and future programs are **UNPROVEN**. These limitations are not waived by the
absence of declared ELF load-time dependencies.

## Failure history and validation scope

Earlier isolated attempts are preserved, not counted as passing:

- Podman's bare config ID was initially compared with a prefixed ID; fixed by
  strict canonicalization, with malformed-ID negatives.
- The base keyring was not initialized; RPM checks failed before installation.
  Fixed by verifying/importing the already pinned key inside the builder only.
- A detached attempt ended without completion evidence during the connectivity
  interruption. It is incomplete infrastructure evidence, not a build result.
- The first complete preparation rejected an expected inventory missing the
  key record. The independent key-only probe established the exact delta; the
  corrected locked preparation then passed.
- Source review caught a compilation cleanup variable collision before any
  compilation ran; the exact owned container name is now preserved and tested.

The successful preparation, two compilations, ELF checks and original-base
smoke use the native source revision stated above. Source review then caught
that any nonzero Podman result was insufficient proof of a missing input. At
`393fd4b1fae9a56e75b76ab142b7ec8949d4ba60`, the corrected controls were executed
against the **same** immutable builder, without repeating preparation or the
successful compilation. Both verified the original inputs, removal and exact
missing-input cause: rustc exit **72**, static libc exit **73**. Infrastructure
or unrelated errors cannot satisfy these controls. Original weaker transcripts
remain preserved and are not used as the final negative proof.

Final focused tests pass **74/74** on macOS and the original Fedora base,
rootfs fixtures **76/76** on that base, complete tooling **111/111**, and the
existing Candidate C harness **5/5**. Python compilation, relevant Bash syntax,
inventory comparison and structural release preflight pass. Local Cargo is
unavailable, so actual local `cargo metadata` remains **UNPROVEN**; Cargo's
installed version inside the builder was measured. The historical unrelated
boot-suite 72/73 result is unchanged, not rerun or claimed fixed. Exact counts,
commands and source fingerprints are in the
[machine-readable evidence](../evidence/0.0.4-f5-static-toolchain.json).

Commands and evidence boundaries are documented in the
[test instructions](../../tests/podman/static-toolchain/README.md). Raw native
outputs, both binaries and the exact RPM cache remain in the isolated
development workspace. Bounded copied transcripts are ignored under
`image/build/output/f5-static-toolchain/`; binaries and RPMs are not committed.

## Preserved boundaries and remaining gates

The reviewed P3-1c source rootfs recipe, golden manifest/build identity and
fixture source are unchanged. This binary has **not** been inserted into that
rootfs or production CoreOS. The separate toolchain contract is explicitly an
unapproved development review record; it is not installed-artifact certification.
The existing build contract gains only hashes for the two new configuration
records; its accepted source-inventory baseline is not regenerated.

The F5 glibc mismatch is resolved for this isolated build-only fixture path.

review/acceptance, dedicated installed SELinux behavior, ancestor/mount checks,
management identity integration, reset/native recovery and A-to-B-to-A remain
separate **UNPROVEN** gates. Reproducible fixture bytes do not imply a
reproducible builder image, production acceptance or permission to begin P3-1d.
No OS image, qcow2, KVM test, production deployment or release was made here.
