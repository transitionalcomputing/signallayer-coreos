- **Status:** Pass 5 packaging cleanup complete; final regression failed manual acceptance
- **Date:** 2026-10-20

## Scope and implementation

This maintenance change addresses issue #27 by appending `loglevel=5` to the
existing qcow2 kernel arguments. Both `console=tty0` and
`console=ttyS0,115200n8` remain configured. The change does not use `quiet`,
disable audit or SELinux, modify D-Bus or SELinux policy, grant privileges, or
change the appliance-console services. Kernel warnings and higher-severity
messages remain eligible for console output; notice-level audit records remain
available to persistent journald without sharing the interactive terminal.

The maintained boot harness now has a focused `--console-audit` mode. Its guest
probe stimulates the known bootc audit path, records persistent audit evidence,
emits notice/warning/error kernel sentinels, captures the serial stream, and
requests four QMP framebuffer screenshots around the stimulus and harmless
operator input. The evaluator also retains system health, console confinement,
capability, policy-integrity, immutable-mount, and write-rejection checks.

## Pass 4 diagnosis and correction

The remaining line is not an audit record with an unexpectedly high severity.
When no userspace audit daemon is registered, the kernel's
`kauditd_hold_skb()` fallback calls `kauditd_printk_skb()`. That function calls
the global `printk_ratelimit()` before emitting each audit record at
`KERN_NOTICE`. When the burst is exceeded, generic `___ratelimit()` emits its
own `"%s: %d callbacks suppressed"` summary through
`printk_deferred(KERN_WARNING, ...)`. A console threshold of 5 therefore hides
the notice records but admits the warning-level summary.

The five consecutive Session1 requests deliberately make the regression
deterministic by producing several bootc audit records inside one rate-limit
window. They amplify the condition but do not invent it: suppression summaries
were also captured during ordinary boot, and the original field report involved
the same no-auditd fallback under recurring platform-status reads.

The scoped correction installs and enables Fedora's standard `auditd` service.
It registers the kernel audit unicast consumer, so successfully delivered audit
records no longer enter the no-daemon printk fallback. The kernel still sends
the independent audit multicast copy consumed by journald, and auditd also
persists its own `/var/log/audit/audit.log`. No custom audit rules, SELinux
allow rules, capabilities for SignalLayer services, or lower console threshold
are added. `loglevel=5` remains, preserving ordinary warning/error visibility.

The guest probe now requires active auditd state and proves the expected records
exist in both persistent journald and auditd's log. The evaluator examines only
the serial portion after the appliance UI first renders and rejects audit
records, AVC/SELinux markers, and `kauditd_printk_skb` suppression summaries.
This closes the false-positive that allowed the Pass 3 machine report to pass.

Focused evaluator tests passed 7/7; the complete maintained boot-harness test
set passed 64/64. Python compilation, shell syntax, and `git diff --check`
passed.
