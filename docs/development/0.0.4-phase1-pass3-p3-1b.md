## Implemented code

[identity.py](../../management-lifecycle/identity.py) uses Python's standard
library; Python 3 already appears in the pinned Fedora base NEVRA measurement.
It adds no runtime package or installed helper. The module has no CLI, service,
subprocess or generic command interface. Public `provision()` takes no
arguments, requires UID/EUID 0 and selects fixed paths; private stores permit
only disposable fixture substitution in this pass.

- Read/validate: complete passwd/group/shadow/gshadow snapshots, subordinate
  mappings and strict versioned recovery metadata. Reject duplicate names or
  IDs, unresolved owners, partial/malformed/oversized records, overlaps,
  overflow, unexpected ownership/types/modes, symlinks and hardlinks. Complete
  short reads and reject a file changed during the read. Account files may not
  be executable or capability-bearing.
- Plan: choose a free machine-local system UID/GID in 100–999, then the lowest
  free 65,536-aligned range at/above 100000. Exclude all local primary IDs and
  both subordinate mapping spaces. Never adopt an ambiguous unrecorded
  `sl-management` account; leave `sl-runtime` and other accounts untouched.
- Apply: fixed recovery `identity.lock` plus standard `/etc/.pwd.lock`,
  nonblocking acquisition, fsynced intent, independent atomic replacements of
  the six account files, final validation, then fsynced committed metadata.
  No multi-file atomicity is assumed. Intent contains only accepted values and
  before/after hashes, not copies of other users' credentials.
- Recovery: after interruption, each file must match its recorded before or
  after state. Complete only the exact missing writes, otherwise refuse with
  recovery diagnostics. Never destructively roll back unrelated accounts.
  Existing application/runtime state blocks initial allocation and partial
  mapping completion. A committed identity never silently reallocates.
- Policy: locked password and group credentials, exact noninteractive shell
  and home, no supplementary/admin membership. No user-manager or runtime
  execution authority is provided. Existing xattrs/modes are preserved; new
  metadata is private. Live NSS requires files-first `passwd`, `group` and
  `shadow` using only `files`/`systemd`. The sole accepted action is
  `[SUCCESS=merge]` between accepted `group` providers. An explicit `gshadow`
  policy uses the same `files`/`systemd` restriction as `shadow`. `subid` must
  be absent or exactly `files`; absent-entry acceptance follows shadow-utils
  4.19's documented local-files fallback. `initgroups` must be absent or use
  only the accepted `group` providers. UID/GID/name/range corroboration remains in place. Existing local
  management accounts require effective membership checking through
  `getgrouplist`, not just `getgrall().gr_mem`; first creation requires a
  pre-allocation check and post-creation recheck before commit. Missing,
  unreadable or unsupported identity policy fails closed without changing
  host configuration; this does not certify installed NSS.

`config/coreos-source-inventory.json` changes only planned metadata: issue #41

## PR #42 review-correction checkpoint

The bounded source correction addresses N1–N2: `subid`/`initgroups` cannot route
around the supported local identity providers; the Fedora-shaped local policy
can express `shadow: files systemd` and
`group: files [SUCCESS=merge] systemd`. NSS read errors must remain structured
refusals naming `etc/nsswitch.conf`, including a no-follow symlink refusal.
These parser rules do not authorize following authselect-managed symlinks or
certify that the installed image selects this local profile. The unchanged
`O_NOFOLLOW` guard refuses an authselect-managed `etc/nsswitch.conf` symlink
with a structured diagnostic; this compatibility limit is not repaired by a
new path allowlist or link-following rule in this pass. Effective supplementary
membership must use `getgrouplist` for an existing local account and include
checks before allocation and after creation before commit; a `getgrall` result
alone cannot prove the no-admin-membership invariant. Shadow-utils 4.19's
`lib/nss.c` and `lib/subordinateio.c` document the local-files fallback when
`subid` is absent; this supports that parser choice and does not prove
installed integration.
