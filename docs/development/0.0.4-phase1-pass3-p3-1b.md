## Implemented code

[identity.py](../../management-lifecycle/identity.py) uses Python's standard
library; Python 3 already appears in the pinned Fedora base NEVRA measurement.
It adds no runtime package or installed helper. The module has no CLI, service,
subprocess or generic command interface. Public `provision()` takes no
arguments, requires UID/EUID 0 and selects fixed paths; private stores permit
only disposable fixture substitution in this pass.

- Read/validate: complete passwd/group/shadow/gshadow snapshots, subordinate
  mappings and strict versioned recovery metadata. Reject duplicate names or
  IDs, unresolved owners, partial/malformed/oversized records, overlaps,
  overflow, unexpected ownership/types/modes, symlinks and hardlinks. Complete
  short reads and reject a file changed during the read. Account files may not
  be executable or capability-bearing.
- Plan: choose a free machine-local system UID/GID in 100–999, then the lowest
  free 65,536-aligned range at/above 100000. Exclude all local primary IDs and
  both subordinate mapping spaces. Never adopt an ambiguous unrecorded
  `sl-management` account; leave `sl-runtime` and other accounts untouched.
- Apply: fixed recovery `identity.lock` plus standard `/etc/.pwd.lock`,
  nonblocking acquisition, fsynced intent, independent atomic replacements of
  the six account files, final validation, then fsynced committed metadata.
  No multi-file atomicity is assumed. Intent contains only accepted values and
  before/after hashes, not copies of other users' credentials.
- Recovery: after interruption, each file must match its recorded before or
  after state. Complete only the exact missing writes, otherwise refuse with
  recovery diagnostics. Never destructively roll back unrelated accounts.
  Existing application/runtime state blocks initial allocation and partial
  mapping completion. A committed identity never silently reallocates.
- Policy: locked password and group credentials, exact noninteractive shell
  and home, no supplementary/admin membership. No user-manager or runtime
  execution authority is provided. Existing xattrs/modes are preserved; new
  metadata is private. Live NSS supports only files-first local/systemd
  providers, with UID/GID/name/range/membership corroboration; unsupported
  providers fail closed without changing host configuration.

## Remaining gates and blockers

No blocking source-test failure remains. This is **GO for draft source review**,
not production acceptance. The known boot unit-test failure remains separately
tracked. Before any installed integration, separately authorize and prove:

1. Exact integration into the fixed lifecycle, including how account creation
   and sysusers ordering coordinate with durable intent. No new interpreted
   privileged helper, service or installed executable is authorized here.
2. Actual target NSS policy/dynamic-ID behavior; unsupported providers currently
   refuse. Do not relax this merely to make startup succeed.
3. Loaded SELinux policy and initial labels on newly created metadata/subid
   files; retained-xattr fixtures do not prove relabel authority. Verify actual
   privileged file ownership and cooperation with Fedora account tools.
4. Power-loss/filesystem semantics, real reboot and A→B→A identity preservation,
   and service/Podman confinement at later authorized image/runtime gates.

P3-1c/1d and production deployment have not begun. Preserve the accepted
R1–R10 gates and unaccepted upstream engine risk. Next action: independent
review of this draft PR; no merge or release authorization is implied.
