# SignalLayer CoreOS 0.0.4 Phase 1 Pass 1 findings

## Status and verdict

**CONDITIONAL GO TO RETAIN AS AN EXPERIMENTAL BASELINE.** A root-owned systemd system service successfully launched
and supervised a fixed rootless Podman container as a locked, dynamically
allocated `sl-management` identity without a login, linger, user manager,
host mount, host network, capability, or host-root mapping. It
started again after an in-guest reboot. The tested same-UID attacks could not
change the root-owned bootstrap definition or configuration, control it over
systemd, or write privileged CoreOS paths.

The original review recorded 28/28 from an unmaintained, one-off evaluator.
Reconciliation found that the committed runner did not generate or enforce
those checks: it accepted a clean QEMU exit plus a `complete` marker, silently
discarded malformed records, and did not fail when recorded commands failed.
The new maintained evaluator replays the preserved completed run as **32/34,
FAIL**. `evidence_commands_valid` fails because the preserved `systemd` and
`audit` records exited 127. `host_rootless_socket_absent` also fails: the probe
tested `/run/user/992/podman/podman.sock`, while its fixed `XDG_RUNTIME_DIR`
made `/run/sl-management/podman/podman.sock` authoritative and Podman reported
that path as existing. The evidence cannot determine what object was present,
so host-socket absence is UNPROVEN rather than a confirmed product defect. The
remaining 32 assertions, including the complete serial AVC review, pass. The
probe now tests the correct path, but this post-run correction is future
behavior, not retroactive evidence. Other post-run corrections already
present in `guest-probe.sh` are future behavior, not retroactive evidence.

This is a bounded feasibility result, not Phase 1 acceptance. Identity
collision/interruption cases, an immutable additional image store, dedicated
management SELinux types, private rootless networking, runtime failure
isolation, and lifecycle compatibility remain unproven and retain their later
pass assignments.

numeric ID, locked the account, selected the first aligned 65,536-ID extent

## Rootless system-service result

The root-owned unit fixed the executable, manifest digest, `HOME`,
`XDG_RUNTIME_DIR`, containers/storage configuration, graphroot and runroot. It
used `User=sl-management`, `Delegate=yes`, `--pull=never`, `--network=none`, a
read-only rootfs, NNP, all-capability drop, no mounts, and no published port. Rootless
Podman reported:

```text
rootless=true
graphRoot=/var/lib/sl-management/containers/storage
runRoot=/run/sl-management/containers
graphDriverName=overlay
cgroupVersion=v2
ociRuntime=crun
```

The service was active and enabled after reboot with no interactive login,
linger, or user manager. Podman fell back from its configured systemd cgroup
manager to `cgroupfs` because no user session existed. The host container
process nevertheless remained inside
`/system.slice/sl-management-fixture.service`, which systemd delegated and
supervised. Production acceptance of that explicit fallback remains an
engineering decision; no login/user-manager authority was added to hide it.

Runtime evidence established:

- container UID 0 mapped to host UID 992; remaining IDs mapped to
  `100000:65536`; host UID 0 was absent;
- the host process ran as UID 992/GID 995 with empty permitted, effective,
  bounding and ambient capabilities;
- `NoNewPrivs=1`, seccomp mode 2, and
  `system_u:system_r:container_t:s0:c241,c958` were active;
- the container used `network=none`, had no host mounts, was unprivileged, and
  used the exact fixture manifest;
- inside the container `/etc` was read-only, and rootful Podman and systemd
  private sockets were absent;
- a second boot used a different boot ID and started the service successfully
  without a login.

## Bootstrap-authority attacks

| Attack from unconfined same UID | Result |
| --- | --- |
| append/replace root-owned system unit | denied by DAC |
| create system-unit drop-in | denied by DAC |
| change root-owned storage configuration | denied by DAC |
| start, stop, or restart the system unit | denied by systemd/polkit |
| control through a user manager/bus | no user manager or user-scope bus |
| access rootful Podman socket | denied; the rootful socket did not exist |
| access rootless Podman socket | UNPROVEN; the preserved probe checked the wrong runtime path |
| write `/etc` or `/boot` platform state | denied; `/boot` was read-only |
| hostile per-user container/storage config | ignored; fixed configuration booted the exact digest after reboot |

The container had no route to the host unit, configurations, storage paths,
system bus, or rootful runtime. The container-side socket checks passed, but
host rootless-socket absence remains UNPROVEN because the preserved host probe
checked the wrong path. As recorded by the architecture contract, a native
process that fully compromises the runtime UID still controls that UID's
writable Podman store. Pass 2's immutable source store and later
control/workload identity decisions remain necessary.

The deliberate missing/corrupt-service case and proof that every native
platform/recovery service remains usable are **UNPROVEN** in this base-only
experiment. The completed run had zero failed units, powered down cleanly, and
did not alter its source disk.

Current main adds the 0.0.3.1 console/audit correction and mandatory release
preflight. Those changes do not contradict the system-service hypothesis, but
the preserved run used a pinned Fedora base rather than the current CoreOS
payload. It therefore cannot prove compatibility with current native services,
audit behavior, release identity, or lifecycle recovery.

Pass 2 must independently prove rootless, identity-independent consumption of
the OS-owned read-only additional image store. It must not treat the writable
fixture store used here as accepted design. It should retain the system-service
candidate and machine-local identity model, explicitly decide the no-login
`cgroupfs` behavior, and preserve the same authority attacks. This pass stops
without starting that work.
