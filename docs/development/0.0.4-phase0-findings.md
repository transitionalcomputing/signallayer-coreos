# SignalLayer CoreOS 0.0.4 Phase 0 findings

**Status:** PHASE 0 FINDINGS — ARCHITECTURAL REVIEW REQUIRED

**Measured:** 2026-10-19 on `slit-coreosdev-01`, Fedora 44 x86_64

**Repository baseline:** `1674cc4` (merged PR #22)

**Pinned base:**
`ghcr.io/transitionalcomputing/signallayer-base@sha256:ef8a660e5b1aa24f8b35c43caa57e972f280766c7980440f4490193bf987df2c`

**Pinned base image ID:**
`d312275bca51c0a0e28a30b5fe75d8027f540a21713934b84a35f77174e3ef7b`

This report records the read-only investigation required by
[the 0.0.4 plan](../milestones/0.0.4-plan.md). It does not authorize or claim
Phase 1 implementation. Terms have the following meanings:

- **MEASURED:** observed directly in the pinned image or existing builder.
- **DOCUMENTED:** stated by the exact installed man page or authoritative
  upstream documentation.
- **PROPOSED:** recommended for architectural approval; not implemented.
- **DEFERRED:** requires a Phase 1 image and genuine-KVM runtime evidence.

## Executive finding

No fundamental Fedora 44 dependency blocker was found. The pinned base already
contains the complete candidate runtime set, including Podman, Quadlet, crun,
conmon, container-selinux, `pasta`, subordinate-ID helpers and overlay helpers.
Phase 1 should use and assert those pinned-base versions rather than update from
moving Fedora repositories.

Podman 5.8.7 supports the required rootless Quadlet and security-label keys.
The shipped containers/storage configuration already names
`/usr/lib/containers/storage` as a read-only `additionalimagestores` path.
The feasibility of a dedicated SELinux process domain and data type is supported
by the installed policy interfaces, but the actual transition and equal-MCS
isolation remain Phase 1 loaded-policy gates.

Phase 1 is **ready for architectural review, not yet authorized**. The
independent architecture review rejected globally fixed IDs, a root-owned
Quadlet symlink as sufficient bootstrap authority and one writable graphroot
shared across potentially incompatible deployments. The reconciled preferred
experiments and their stop conditions are recorded below; none is implemented
or validated by this report.

## 2. Rootless identity and subordinate mappings

The pinned base is **MEASURED** with UID/GID 976 free and empty `/etc/subuid`
and `/etc/subgid`. This is fresh-image evidence only. Existing 0.0.3 machines
already allocate SignalLayer system users dynamically, so 976 or the proposed
builder-adjacent subordinate range may be occupied during an upgrade.

**RECONCILED INVARIANT:** `sl-management` is locked, noninteractive and stable
for the lifetime of one machine's runtime state. Its numeric UID/GID need not be
identical across machines. `sl-runtime` remains reserved for future workload
infrastructure and must not share the management identity or subordinate maps.

**PROPOSED provisioning experiment:** an early root-owned, idempotent provisioner
must resolve or allocate a collision-free system UID/GID, allocate one aligned
and non-overlapping subordinate UID and GID extent of at least 65,536 IDs, and
persist the accepted identities in `/etc` plus root-owned recovery metadata.
It must reuse the same values across reboot, update, rollback and recovery;
refuse malformed, partial, overlapping or changed mappings once runtime state
exists; and complete before Podman can open storage. No builder-local numeric
mapping is a target reservation.

Phase 1 must include a 0.0.3 upgrade fixture with 976 occupied, interrupted
provisioning and two machines using different numeric mappings. Immutable image
content must not encode the machine-local UID or subordinate range unless an
approved construction proves that dependency unavoidable.

## 3. Bootstrap authority and systemd

The installed Quadlet 5.8.7 man page and generator **MEASURED** that rootless
Quadlets use a real user manager and search, in order, writable runtime/config
paths before `/etc/containers/systemd/users/<UID>` and the global `/etc` path.
This version has no distribution rootless search path below `/usr/share`.

A root-owned symlink from the per-UID `/etc` path to immutable `/usr` therefore
does **not** by itself establish bootstrap authority. Higher-priority Quadlet
paths, systemd user-unit drop-ins, transient units and the user bus add same-UID
control surfaces.

**LEADING EXPERIMENTAL MECHANISM:** a root-owned systemd system service invokes
the fixed rootless Podman command with `User=sl-management` and CoreOS-owned
configuration. This avoids normal user-manager Quadlet and user-bus override
paths, but `User=` alone does not prove a correct rootless environment. The
first genuine-KVM experiment must establish fixed `HOME`, `XDG_RUNTIME_DIR`,
storage/runroot, subordinate mappings, user namespace, cgroups v2 and SELinux
transition without login or an unrestricted Podman socket. The identity must
be unable to alter the service or control privileged units.

Rootless user Quadlet remains an alternative only if loaded policy and runtime
tests prove that the management container and all same-UID workload processes
cannot write any higher-priority generator/unit path, reach the user bus, create
transient overrides or replace the generated service. The bootstrap mechanism
is unresolved until the two approaches are compared under genuine KVM.

## 4. Immutable management image store

The pinned `/usr/share/containers/storage.conf` is **MEASURED** with overlay and
`/usr/lib/containers/storage` in `additionalimagestores`. The base carries an
empty root-owned store skeleton there. Upstream documents additional image
stores as normally read-only and warns that a per-user `storage.conf` replaces,
rather than merges with, system configuration.

**PROPOSED:** retain `/usr/lib/containers/storage` as the preferred CoreOS-owned,
read-only store, populate exactly one digest during the CoreOS build, and keep
the consumer's storage configuration root-owned.

Feasibility remains **SUPPORTED BUT UNPROVEN**. A root-created store must be
traversable/readable on machines with different management UID/subordinate
mappings without making layer contents broadly host-readable. Upstream's
`force_mask=shared` path is not authorized because it broadens host readability
and requires a mount program. Store construction, DAC ownership, ID-map
independence, xattrs, SELinux contexts, storage format, digest resolution and
offline use require genuine-KVM Phase 1 evidence.

## 5. SELinux isolation mechanism

The pinned `container-selinux` package **DOCUMENTS** custom container-domain
interfaces, but the ordinary container-domain template introduces a substantial
inherited permission and attribute surface. It is an experimental starting
point, not evidence of least privilege.

**PROPOSED:** maintain three distinct label roles:

1. a dedicated management process domain;
2. a container root-filesystem/image file type; and
3. a persistent management-data file type.

Persistent data receives deterministic file contexts from maintained policy or
CoreOS-controlled provisioning. It must not acquire a generic container-file
attribute unless loaded-policy analysis proves the contract is preserved, and
it must never be relabeled by a container mount. Do not classify the management
process as a container runtime.

Another `container_t` process deliberately assigned the same MCS categories
must still be denied by type enforcement. Phase 1 must inspect expanded loaded
policy, exercise type-request spoofing and verify runtime, systemd and recovery
access. Policy compilation, `ps -Z`, EROFS denial or absence of AVCs alone do
not prove the boundary.

## 6. Security-label directives

Podman 5.8.7 **MEASURED** support for:

```ini
SecurityLabelType=sl_management_t
SecurityLabelFileType=sl_management_rootfs_t
```

A disposable Quadlet dry-run translated these to process and container-file
security options. `SecurityLabelFileType` is not a mechanism for labeling an
existing persistent bind source. Persistent mounts must omit both `:z` and
`:Z`; their dedicated data labels are established before container start.
Transition feasibility, effective inherited permissions, type spoofing and
fixed-data-label preservation remain **DEFERRED**.

## 7. Networking and storage selection

### Networking

The pinned configuration **MEASURED** `pasta` as the rootless helper, with
`slirp4netns` absent. **PROPOSED:** retain explicit `Network=pasta` and publish
no ports. Lack of a published port does not prove isolation from host services.
Phase 1 must inventory listeners and test namespace identity, host loopback and
global-address access, IPv4/IPv6 gateways, DNS forwarding, offline startup and
fail-safe behavior when `pasta`, a route or DNS is unavailable.

### Storage

The builder uses native rootless overlay on XFS, but this is not guest evidence.
**PROPOSED:** select native rootless overlay and fail before bootstrap if the
guest selects VFS or `fuse-overlayfs`. Leaving the installed helper unconfigured
is insufficient because containers/storage may auto-select it when native
overlay probing fails. Record the actual driver, native-overlay status, mount
program, backing filesystem, mounts and helper processes. Any fallback requires
separate architectural review.

## 8. Runtime reconstruction

The immutable image store, epoch-specific engine graph, persistent application
data and root-owned recovery metadata are separate authorities:

| State | Proposed ownership | Recovery rule |
| --- | --- | --- |
| Accepted image/store metadata | CoreOS `/usr`, root, read-only | Replaced and rolled back with deployment |
| Engine graph/writable layer | compatibility-epoch child under `/var/lib/sl-management/containers/` | Disposable only while verified stopped |
| Runroot | explicit location resolved for the machine-local identity | Ephemeral each boot |
| Management application data | separate typed bind mount | Preserved across reconstruction/update/rollback |
| Compatibility/recovery record | native CoreOS root | Selects epoch and records interruption state |

**PROPOSED reconstruction:** a CoreOS-owned operation inhibits the exact
bootstrap service and proves no Podman, conmon, container process or mount uses
the selected graphroot. It resolves bounded paths without following untrusted
symlinks, verifies device/inode/type/owner/label, atomically quarantines only the
selected graphroot, records an interruption-safe operation state, recreates only
graph/runroot and fsyncs the parent. It never follows or deletes application
data and never automatically deletes quarantined evidence. Recovery must work
when Podman and the Management Plane are absent.

Phase 1 must prove idempotent recovery after interruption, full disk, symlink or
mount substitution and concurrent restart attempts, while management-data
hashes, ownership, mounts and labels remain unchanged.

## 9. Rollback compatibility

The measured Podman package drift demonstrates that an older deployment cannot
be assumed to understand a newer engine database. A compatibility check made by
invoking Podman may already be too late if opening storage performs migration.

**PROPOSED:** assign a CoreOS-owned compatibility epoch to each deployment/runtime
format. A root-owned guard selects an epoch-specific graphroot and validates its
identity, mapping and compatibility record before any Podman command executes.
An incompatible deployment fails closed with native recovery available; it must
not open, migrate or reset another epoch's graph. Application-data schema
compatibility is independent and requires its own versioned migration/rollback
contract.

Epoch assignment, reuse and fallback rules remain unresolved. Phase 1 must prove
stop/reconstruct/start within one epoch and rejection before Podman on mismatch.
Full A→B→A graph, label and application-schema behavior is a later genuine-KVM
release gate.

## 10. Decisions and Phase 1 prerequisites

### Reconciled dispositions

| Decision | Phase 0 disposition |
| --- | --- |
| Runtime packages | Assert pinned-base NEVRAs; no moving-repository update |
| Identity | locked, machine-persistent `sl-management`; collision-safe allocation; reserve `sl-runtime` |
| Subordinate IDs | machine-allocated, non-overlapping, persistent extent; fail closed on drift |
| Bootstrap | compare CoreOS-owned system service with isolated user Quadlet; neither selected yet |
| Image delivery | preferred `/usr/lib/containers/storage`, digest verified; KVM proof required |
| Storage | native rootless overlay only; VFS/FUSE fallback is a stop condition |
| Network | explicit `pasta`; measured host-reachability and failure behavior required |
| SELinux | distinct process, container/rootfs and persistent-data types |
| Graphroot | compatibility-epoch-specific and selected before Podman |
| Recovery | CoreOS-authorized, symlink-resistant, interruption-safe and data-preserving |
| Rollback | older deployment never opens incompatible newer graph metadata |

### Human decisions required before Phase 1 implementation

1. Approve machine-persistent identity and collision-safe subordinate-map
   provisioning, including 0.0.3 upgrade and interruption behavior.
2. Approve the system-service experiment as the leading bootstrap candidate and
   user Quadlet only as a measured alternative; neither is selected yet.
3. Approve compatibility-epoch graphroots and define the pre-Podman guard,
   epoch assignment and rollback selection rules.
4. Approve the immutable store, native overlay and `pasta` only as experimental
   candidates subject to their stop gates.
5. Approve the three-type SELinux model while retaining template expansion,
   transition/spoofing and equal-MCS loaded-policy proof as stop conditions.
6. Define the minimal non-product fixture and exact native recovery operation
   before either becomes implementation scope.

No Podman socket, rootful container, host network, broad volume, unconfined
label, generic systemd control or second machine authority is authorized. Phase
1 must stop for contract review if any becomes necessary.

## Reproduction summary

All target-image measurements used the already-present pinned image with
`podman run --rm --pull=never`; package-version queries used either
`--network=none` or repository metadata in a disposable container. No packages
were installed, no image was pulled or built, and all temporary container
directories were removed with their containers.

Representative commands:

```bash
IMAGE=ghcr.io/transitionalcomputing/signallayer-base@sha256:ef8a660e5b1aa24f8b35c43caa57e972f280766c7980440f4490193bf987df2c

podman image inspect "$IMAGE"
podman run --rm --pull=never --network=none "$IMAGE" rpm -q \
  podman crun conmon container-selinux systemd containers-common \
  netavark aardvark-dns passt fuse-overlayfs shadow-utils shadow-utils-subid
podman run --rm --pull=never "$IMAGE" dnf -q repoquery \
  --latest-limit 1 podman crun conmon container-selinux systemd
podman run --rm --pull=never --network=none "$IMAGE" \
  /usr/libexec/podman/quadlet --version
podman run --rm --pull=never --network=none "$IMAGE" sh -c \
  'grep -n additionalimagestores /usr/share/containers/storage.conf'
```

The Quadlet translation tests used `QUADLET_UNIT_DIRS` only inside a disposable
container with the documented generator `--user --dryrun` mode. No container
workload was started by those tests.
