## Accepted limitations

This milestone retains the limitations documented in the
[0.0.3 release notes](../releases/0.0.3.md), including:

- x86_64 KVM/OVMF is the validated platform; Secure Boot, physical hardware and
  other architectures remain unvalidated;
- the qcow2 has a development-local bootc origin and no production update
  channel is published;
- update and rollback activation require explicit operator reboots, with no
  automatic health-triggered rollback or boot-attempt policy;
- no installer, separate recovery environment, Linux login, SSH provisioning
  workflow or general-purpose shell is provided;
- remote management is single-operator, LAN-only and read-only, using a
  self-signed TLS identity and application-level on-link admission;
- the durable management-plane UI and managed Podman workload model remain
  deferred;
- console-authentication proof hardening, Session1/authd decoupling, nftables
  defense in depth and composefs verity evolution remain future work.

These items were not required for the 0.0.3 Developer Preview contract and are
not represented as completed.
