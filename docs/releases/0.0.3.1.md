## Console correction

SignalLayer CoreOS 0.0.3.1 corrects kernel audit output that could displace the
trusted appliance interface on `tty1` and `ttyS0`.

- The image starts Fedora's audit daemon so the kernel retains its audit
  unicast consumer instead of falling back to console printk output.
- The image kernel arguments set `loglevel=5`. Kernel warnings and errors stay
  visible; notice-level messages no longer share the appliance console.
- Audit records remain available through auditd and persistent journald.
- Existing console ownership, authentication, SELinux confinement, capability,
  D-Bus, and immutable-root boundaries are unchanged.

## Validation evidence

The validation-only candidate qcow2 with SHA-256
`aa5aeb2f0980f881ff54613e7f41d4fc2460f88f7c339a432fa974d1e73906b6`
passed the repaired focused harness **28/28** under genuine x86_64 KVM/OVMF.
Serial review found no audit output while either appliance-console service was
active. Framebuffer review confirmed the graphical menu and a meaningful
`Unknown selection.` response to injected harmless input. SELinux remained
Enforcing; audit retention, console confinement, zero capabilities, policy
integrity, system health, immutable mounts, rejected writes, clean shutdown,
and unchanged source-disk identity passed.

This candidate is evidence that the correction works. It is not the final
0.0.3.1 release artifact because its embedded product version, OCI version,
bootc origin, build ID, and filename retain 0.0.3 identity.

## Known limitations

The accepted limitations of the
[0.0.3 Developer Preview](https://github.com/transitionalcomputing/signallayer-coreos/blob/main/docs/releases/0.0.3.md#known-limitations)
remain. In addition,
kernel notice-level messages are intentionally absent from the appliance
consoles; persistent logging remains authoritative for those records. GRUB
branding is tracked separately by issue #28 and is not part of this correction.
