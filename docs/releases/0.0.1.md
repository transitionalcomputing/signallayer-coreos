## Validated capabilities

- UEFI boot under QEMU/KVM into systemd with NetworkManager networking.
- Immutable, read-only system root with composefs enabled.
- Confined `sl-platformd` and `corectl status` using Platform API version 0.1
  and status schema 0.2.
- Root-only update staging through the fixed `bootc upgrade --quiet` worker.
- Explicit operator reboot into the staged deployment.
- Root-only retained-deployment rollback selection through the fixed
  `bootc rollback` worker, followed by an explicit operator reboot.
- Complete fresh A -> staged B -> booted B -> offline rollback -> exact A
  lifecycle under genuine KVM.

The platform boundary is `corectl` -> system D-Bus -> confined `sl-platformd`
-> fixed systemd workers -> bootc. Status is read-only for local users;
deployment mutations are root-only and accept no caller-controlled command,
unit name, or bootc argument.

## Acceptance evidence and final artifact

Phase 3F lifecycle acceptance passed 37/37 checks at milestone
`897ca0521b2d7f0c8541ce64a6edb1877194c90b`. That milestone is historical
Golden Master evidence, not the identity of the final distributed artifact.

The final tagged release was compared with that accepted Golden Master. Package
composition was identical; the only expected flattened root-filesystem
difference was `/usr/lib/signallayer/release`, containing the final source
revision and build ID. A final smoke boot of the tagged release then passed
36/36 checks under genuine KVM. The final distributed artifact identities are
the values in [Published artifacts](#published-artifacts) and the
[provenance record](0.0.1-provenance.md).

## Known limitations

- Only x86_64 KVM with OVMF UEFI was validated. Secure Boot, physical hardware,
  and other architectures were not validated.
- NetworkManager, DHCP, a guest address, and a default route were validated;
  broad external Internet and DNS behavior are not a release guarantee.
- The qcow2 uses `localhost/signallayer-coreos:0.0.1` as its bootc origin. The
  lifecycle used a local development registry fixture. Public registry origin
  configuration, TLS, and authentication were not validated.
- Update activation and rollback activation each require an explicit operator
  reboot. Rollback is manually selected; there is no automatic health-triggered
  rollback or boot-attempt policy.
- There is no separate recovery environment or installer workflow.
- The development qcow2 provisions no login, password, or SSH workflow.
- Composefs `verity=false` remains inherited and accepted.
- Fedora's `install_t` is the intentionally trusted deployment-mutation domain.
- Release artifacts are not cryptographically signed.

Installation and provisioning are expected to evolve substantially after
0.0.1. The qcow2 is an evaluation/development artifact, not a production
installation workflow.
